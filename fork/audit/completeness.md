# completeness

## Summary

The clone-run work is solid where it was tested: 89 files and 21,529 added lines, a referee that really recomputes from files (I deleted all its outputs on a copy of the blind trial's run folder and got the identical verdict), and a verdict that costs 940 tokens. What was missed first is the proof that agents can use it: milestone 1's own acceptance test (one headless agent reaching exit 0, with tokens and time printed) was turned into a non-goal, the only agent run on an unseen application ended `stalled` after 47 minutes and about 73 captures, it replays today as `not_done` on one unknown only a person can waive, and no token count exists for any run. Second, `done` certifies the probed steps only: the trial's judge found at least 7 real differences no step probed, coverage (milestone 2) is not started, and a waiver any agent can write makes the run exit 0. Third, context: the behaviour tables the builder is told to read were designed at 10 to 20 KB and measure 174 to 647 KB per scenario (2.28 MB for five) on the trial, and the playbook's own 'read one step' commands cost 2,056 to 15,947 tokens a call; storing repeated page text once would cut the tables by 64 to 75%. Fourth, scope: sign-in, any page request to another origin (92% of pages have one), dates shown on screen and replies over 64 KiB all fall outside, and the last one plus the ban on secrets and storage are limits the renderer and the scenario schema impose themselves, not limits of the capture command. Fifth, the branch has never met the repository's own gates: about 39 of 3,832 test files were run, always as root on one Linux container, no CI run exists, and `npm run check`, `verify:package`, macOS and Windows were never tried; the light checks I could run are clean (typed lint 0 errors on the changed files, 0.21% duplication, 129 of 129 internal doc links resolve, a pack dry run ships nothing extra). Every capture command the referee prints starts with `timeout`, which stock macOS does not have, and the verifier refuses Windows. The fork's CLI calls itself 6.9.0 like upstream's, upstream published 6.10.1 the next day, and the skill still tells an agent without `rea` to use `npx -y rea-agents@latest`, which lacks all three commands. New in this audit: clone runs move agents off MCP, the only channel that carries upstream's untrusted-content marker, while gate messages and behaviour tables carry the original's text and the skill never says to treat it as data. Of 58 statements I sampled from the spec, reference page, playbook and design, 12 have an automated test, 10 rest on a run only, 8 on code only, 9 are partly backed, 7 have nothing, and 12 are contradicted, stale or wrong as written. `evaluateCloneRun` is one function of 890 lines and complexity 167, fourth in the whole repository on both counts, and none of the owner's eight decisions has a recorded answer.
