# Run r1: the task benchmark before and after the router skill

One agent label (`a1`), one sample per cell, nineteen cells per build. Before is commit 0e089b3e (the long
skill body). After is 3eb71f14 (the router skill and nothing else that changes context). The two builds'
cells were interleaved so both met the same machine load. Scores: `2026-11-21-r1-before.json` and
`2026-11-21-r1-after.json`.

## What it shows

| | Before | After |
| --- | --- | --- |
| Tasks right | 18 of 18 | 18 of 18 |
| Facts right | 61 of 61 | 61 of 61 |
| First command as expected | 17 of 18 | 17 of 18 |
| Largest peak context | 153,772 tokens | 100,769 tokens |
| Prompt tokens, all turns, all cells | 15.9 million | 12.0 million |
| Bytes read from the skill, all cells | 1,058,408 | 204,630 |
| Bytes REA printed into context, all cells | 367,640 | 352,749 |

The floor (an agent that only writes a trivial answer) is about 67,800 tokens of peak context. Net of it, a
simple one-inspector task costs about 30,000 tokens before and about 14,000 after.

## What it does not show

- One sample per cell: no variance. A difference in one cell is an anecdote.
- Every task is answered right on both builds, so this agent and this task set cannot show a difference in
  accuracy. A weaker agent or harder tasks are needed for that.
- What REA prints did not change between these builds; the answer budget is not in either.

## What the agents ran into (their own reports)

Reports named a gap in the guidance 13 times before and 18 times after. The ones that cost turns:

- **No route for the long tail.** OpenAPI files, DWARF debug information and EVM bytecode have no line in
  the first-step list. Agents found the command by searching `rea --help`, and `rea guidance --query` with
  natural words (`openapi`, `debug information source files optimisation`) answered `no_matches`.
- **The summary path can cost more than the full output.** For the HAR task the after-run asked for a
  summary and then needed thirteen turns to page the records: the view kind is only discoverable from the
  full schema, the evidence-file source refuses a bundle with a message that does not show the working
  form, and `--filter-output` accepts only the `[start,end]` slice. The before-run wrote 70 KB to a file and
  read fields from it in six turns.
- **A native binary with no analysis provider installed.** Both runs lost many turns (28 and 19) trying
  commands that all refuse, before finding that `inspect-with-objdump` or `debug-with-gdb` can read the code
  without a provider. Neither skill says so, and the refusal is long.
- **CLI spellings.** Positional arguments (the `hex` encoding of the EVM inspector, the capture kind of the
  HAR inspector) are learned only from `--help`.

# Run r2: the same cells with a smaller agent

Label `b1`, same two builds, one sample per cell. Scores: `2026-11-21-r2-before.json` and
`2026-11-21-r2-after.json`.

| | Before | After |
| --- | --- | --- |
| Tasks right | 18 of 18 | 16 of 18 |
| Facts right | 61 of 61 | 59 of 61 |
| First command as expected | 17 of 18 | 17 of 18 |
| Largest peak context | 142,872 tokens | 133,098 tokens |
| Prompt tokens, all turns, all cells | 21.4 million | 19.2 million |
| Bytes read from the skill, all cells | 965,436 | 136,488 |
| Bytes REA printed into context, all cells | 872,874 | 800,397 |

With the router skill this agent lost two facts. One sample per cell cannot separate the skill from chance,
but each loss has a cause that is worth fixing whatever the variance:

- **The licence-check task (a native binary, no analysis provider installed).** The after-run found the
  function and the key length through `inspect-with-objdump` and left the accepted key out: nothing told it
  that `debug-with-gdb` can read a string from the file without running it. The before-run found that
  command by itself after nineteen turns. Neither skill names it, in the body or in a reference, so this
  difference is the agent's persistence on one sample, not the skill.
- **The page-click task.** Both runs captured the request. REA returns a request body as base64; the
  before-run decoded it outside REA, the after-run read the brief's rule against other tools strictly and
  left the field names out. A text body returned as text would have answered both.

This agent also used about twice the bytes of REA output the first agent did (800 KB against 353 KB), mostly
by calling without the summary form, and the HAR task took it 24 turns on the after build against 15.
